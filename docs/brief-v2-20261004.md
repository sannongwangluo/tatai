## 契约

- task_brief 默认 detail=summary，仍只调用一次 project_entry、使用原完整判据。next_action、有效基线、角色能力、版本、同步阻断、当前运行和必读材料不裁剪。
- 每条理由都留 code、blocking、task_id（如有）和短摘要，不删除未知理由或非阻断提示。省略任务说明/长字段时明确标识，摘要不是完整执行依据。当前选中任务的理由与执行约束完整保留。
- 同步修复计划（V09-48 新增的 `sync.repair_plan`）：summary 只给紧凑导航（现形批次/逐 verdict 计数/阻断与等待计数 + 结构化 refetch 到 `read_sync_status(project_id)`，逐项 `expected`/`actual`/原因/候选不内联）；`detail=full` 与 `read_sync_status` 保留完整逐项。旧字段语义不变，缩略仅作用于新增的 `repair_plan`。
- detail=full 返回上一版完整简报。detail=reason 按 reason_index 与 reasons_revision 取一条完整理由；版本不符、非法参数或索引越界显式报错，不把旧索引套用到新状态。补取时仍核当前事实，不缓存旧绿。
- 阻塞判定不从摘要重算；原认领、提交、授权及用户 Gate 不变。摘要短不等于授权范围变小或放宽。
- Agent 对阶段材料按 path+range 读取，状态没有变化也没有新动作时不重复获取相同简报。只有明确需要其他章节才扩大读取；必要证据不能因省 token 省略。

## 验收与交付边界

原完整模式行为验证继续通过；新模式覆盖全部理由索引、当前任务约束保留、错误透传、只调用一次、按版本补取、状态变更拒旧索引、无效参数拒绝和只读不变性。使用冻结的真实 24 理由样本比较紧凑 UTF-8 返回体，目标不超过旧简报的 45%；不把字节比例称为模型总 token 节省。
