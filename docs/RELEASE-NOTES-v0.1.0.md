# 塔台（Tatai）v0.1.0 发布说明

> 版本：`v0.1.0`（首个发布）｜ 日期：2026-09-18 ｜ 许可：MIT（见 `LICENSE`）
> 设计事实源：`DESIGN.md` ｜ 施工全历史与验证证据：`PROGRESS.md` ｜ 依赖许可审计：`docs/LICENSE-AUDIT.md`

塔台是**个人级 agent 编程工作台**：你当项目经理，多个 AI agent（Kimi Code、Codex 等）当干活的工人。
它不开飞机，但看得见每一架飞机——**唯一职责是让唯一的用户看得见项目全貌**：进展、架构、设计决策。

它**不是** IDE、**不是**拉起 agent 的调度器、**不是**聊天客户端。

---

## 一、这一版能做什么

### 1. 项目管理与全局视图
- 一张全局注册表管所有项目（项目名 → 目录路径），接入时自动判定项目类型（前端 / 后端 / 前后端 / 静态站），
  并检查该项目 `.gitignore` 是否漏了 `.工作台/` 这一行（私人数据别被提交）。
- 左栏两段：Agent 管理（哪个 agent 最近在哪个项目干活）+ 项目管理。
- **跨项目视图**：一屏一行一个项目，Gate 走到哪一步、模块四色计数、正在做什么一目了然。

### 2. 看得见的进展
- **Gate 七步**时间线：每一步谁定、什么时候定、结果如何，留痕可查。
- **任务与模块状态**：agent 干活时通过 MCP 工具自报任务状态（todo / doing / done / blocked），
  状态自动汇总成模块四色，界面上直接看得出来哪块在动、哪块卡着。
- **变更流**：文件监听记录每一次增删改（增量行只追加、不重写）；跨项目还有一条全局变更流。
- **流程实况**：当前 Gate 步、正在干活的 agent、当前任务 + 变更 / 任务 / Gate 三源对照。

### 3. 看得懂的架构（三视图共享一份数据）
- **模块方框图**：tree-sitter 静态解析各语言顶层模块骨架（Python / JS / TS），依赖边带权重，
  模块名由模型翻成人话（有缓存，不重复请求）；节点可展开下钻到文件级。
- **数据流向图**：同一份静态依赖数据按"谁消费谁"的方向取向渲染，方向着色、粗细表示权重、
  互惠对虚线双向。
- **思维导图**：同一份数据出导图，默认全折叠、点开就地懒加载；上万文件的巨枝自动截断成
  「还有 N 个」聚合节点（不遍历、不解析、不渲染超限部分）。

### 4. 设计书、聊天与落稿
- **设计书**只读展示（markdown 渲染，界面上没有任何编辑入口）。
- **聊天**：与 Flash 聊天，聊完可以让它把讨论提炼成"可落入设计书的条目"，你确认后才落盘。
- **逆向落稿**：给一个老项目，先自己扫（文件树 / README / docs / git 活跃度）+ 读你的历史记忆，
  起草"项目是什么 / 模块划分 / 当前实际阶段 / Gate 标在哪一步"四块雏形，由人定版。

### 5. 终端与记忆
- 内建**终端**：多终端分屏、日志着色、命令历史检索；没回显的口令、敏感形态的输入**不落历史**。
- **记忆检索**：可接你自己的记忆服务（MCP，`mcp.json` 里的 `brain-memory` 条目），
  逆向落稿时用历史记忆补上代码里看不到的决策背景；连不上就降级成"仅代码扫描"，不阻塞。

### 6. 可选的桌面壳与远程访问
- **Tauri 桌面壳**（Windows）：随包后端、单文件安装包、首次运行自动建全局数据目录。
- **远程访问**（默认关闭）：只绑局域网、默认只读、必须 token 鉴权；
  终端历史 / 聊天全文 / 记忆检索默认**都不对远程下发**；写模式要主机上二次确认才开，
  且每一次远程访问都留审计流水。

## 二、怎么跑起来

见 `README.md`（三条命令 + MCP 接入片段 + 桌面壳可选步骤）。最短路径：

```bash
corepack enable pnpm
git clone https://github.com/sannongwangluo/tatai.git && cd tatai
pnpm install
pnpm dev:server    # 后端
pnpm dev           # 前端（另开一个终端）
```

**数据在哪**：全局数据目录 `TATAI_HOME`（缺省 `~/.tatai/`，放注册表、口令、全局日志）；
每个项目的私有数据（设计书、进度、Gate、聊天、变更、架构产物）一律在该项目的 `.工作台/`，**永不进 git**。

## 五、已知限制（据实，不粉饰）

1. **远程访问没有 TLS**：口径是局域网 / VPN 内使用；公网 IP 在代码层直接拒绑。
   README 给了反代 + TLS 的做法与坑（含"反代同机连回环等于把鉴权关掉"这条提醒），
   但**没有起真反代跑过一遍**。
2. **第二台设备未实测**：远程访问只在本机以局域网 IP 真发过请求，**没有从另一台机器 / 手机真发过一次请求**。
3. **MSI 需要管理员**（`perMachine`）；不想提权请用 NSIS 包。
4. **终端历史、终端输出、聊天全文、记忆检索默认不对远程下发**：要主机上显式置位对应环境变量、
   重启后远程才读得到（默认不开是刻意的：这些内容里有本机路径与私人文字）。
5. **项目类型（kind）自动判定有一处待裁**：对"Electron 桌面应用"（`package.json` 只依赖 `electron`）
   会落到兜底 `backend`，与设计书首批试用项目表里写的「前后端」不一致；已在设计书待议区登记，
   不影响架构图渲染。
6. **审计日志没有读取界面**：现在只能用命令（`pnpm remote:write status`、`pnpm remote:token`）
   看写模式状态与口令，审计流水本身要自己开文件看；写模式的"时间段图形化展示"也在待办里。
7. **依赖白名单口径待裁定**：严格按设计书"只接受 MIT / Apache / BSD"字面，
   有 5 个 npm 包 + 28 个 crate 落在白名单外（MPL-2.0 / CC-BY-4.0 / Python-2.0 / Unlicense /
   Unicode-3.0 / Zlib，**均非传染性许可**，多为数据与构建链、或有 `OR` 选择的弱 copyleft）；
   `WebView2Loader.dll` 的微软条款文本未随包。两件事都在设计书待议区登记，等裁定。
8. **只打包了 Windows**：非 Windows 平台既没打包也没实测。
9. **模板的小取舍**：`.工作台.example` 预置了空 `arch/modules.json`，会让新项目第一眼看到
   空图而不是「先解析」引导；想看到引导删掉该空文件即可（`templates/README.md` 已写明）。
10. **依赖本机配置的功能**：聊天 / 起名 / 逆向落稿要 `DEEPSEEK_API_KEY`；
    记忆检索要在 `~/.kimi-code/mcp.json` 里配好对应条目。缺了会明确降级并给原因，不会崩。
