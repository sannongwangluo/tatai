# 能力与边界

> 本页写**当前实现是什么、目标是什么、哪里还没做到**。安装使用见 [`getting-started.md`](getting-started.md)，开发与验证见 [`development.md`](development.md)。
> 设计依据以 `DESIGN.md` 为准；本页是面向使用的概述，冲突时以 DESIGN 与事件账本为准。

## 1. 现在可以使用什么

- 项目登记、目录接入与跨项目概览；七步 Gate 由**用户确认**，任务由 **Agent 自报**。
- **六图**：功能全景／系统架构／施工依赖（三张主视图）＋模块方框图／数据流向图／思维导图（技术详情三张）。逐对象带来源与证据标注，可下钻追到出处。
  - 三张主视图从已审定图纸与代码派生，空仓也有灰色规划图；状态只来自事件与有效证据，界面**不提供人工涂色**。
  - 架构解析在后台运行：有进度、可显式取消、断线/刷新可续看；取消不发布半成品，上次完整结果原样保留并标注原因。
  - **聚合不吞可达性**：概览默认保持防爆炸上限（主视图 5–15 分组、技术层 15 节点/40 边、单枝 40 子级），每个聚合点都有「显示全部／加载全部子级」入口（技术详情画布带搜索定位）。全量模式＝同一套构建器换全量上限：UI 侧＝渲染安全上限 2000 节点/4000 边（超限仍聚合并计数），MCP `mode=full` 侧＝未聚合并集、按 4000 对象/页同一快照分页续取（无 20000 生产上限，20000 档仅存于验证夹具）。采集未完成（`budget_exhausted`）、规则忽略目录、模型补全/提案线索会分别标注，不冒充"全量"。
  - 上限外对象另有**逐项取回**路径（`/api/projects/:id/arch/items` 未聚合并集分页检索＋UI「查看被聚合对象」抽屉、`/arch/expand` 的 `childrenOffset` 稳定分页、MCP full 分页遍历未聚合并集）；游标绑定读取模式（overview↔full 跨模式明确拒绝）。
  - **架构主视图的每个节点带来源档位＋证据状态徽标**（与功能全景／施工依赖共用同一份 `src/ui/arch/provenance.ts` 派生；聚合节点如实标注、不进标注）。
  - 六图以看图为主：画布上方的「来源与证据」信息区**合并成一条**——健康态整条不占常驻行（完整机器读数仍在 `data-*` 与 MCP/HTTP 读口）；有可行动异常时只出现**一条合并问题栏**，完整计数/五档含义/能力分类/逐条阻断与待验进**可关闭、独立滚动**的按需详情。展开／折叠控件的屏幕命中区不随缩放缩到亚像素。
- **七步 Gate 与事件账本**：任务由 Agent 自报、Gate 由用户确认；状态不涂色、不编绿。
- **证据分段失效**：改一份文档只重验受影响的对象（单卡／章节粒度），不再"动一行、全图重验"。
- 设计书展示与显式追加落稿、内置 AI 项目聊天（模型服务可配置）、概念图补全、逆向设计草稿。
- 流程实况、文件变更、终端与 Tauri 桌面壳。终端仍在当前软件中，已移出用户主导航、收进辅助入口的「维护诊断」。
- **Agent 任务认领与执行回执**：认领有 token 门禁，心跳/检查点/交付/效果确认经唯一写入服务落 v2 事件流；断线期间执行端在本地保留待提交回执并暂停领取新写任务，恢复后按原幂等键补交，不重复生效。
- **正向成套图纸入口与上报链**：已有 DESIGN/PLAN 可直接保存并做**技术审定激活**（零差异即可，不要求模型生成）；Agent 的阶段、执行回执、成果、证据与自检/独立审计都有正式 MCP 入口，重试幂等；用于「已验证」的检查绑定服务端实际读取的**有限源码清单**，被覆盖文件变化、删除或不可读即失效或转待复核。
- **用量统计**：项目概览显示任务认领额度（运营节流，不是费用或成本硬限）与事件可配对的执行耗时；Token 与金额没有可核对来源，显式标「未计量」。
- **统一提速与按需取料（2026-10-03 已交付，未升版本、未打 tag、未发 Release）**：一次接续请求内共享同一份账本快照与派生事实（**不跨请求缓存旧绿**，下次调用立刻见新事件，账本中段损坏仍 fail-closed）；只读重计算在**进程内有界工作池**（有界排队、取消、多项目公平），唯一写入宿主承担写；文件读取做**内容校验 + 前缀增量**（识别同长度改写/保留 mtime/截断/中段坏行，不以 size/mtime/TTL 充当内容身份）；MCP 新增 `read_plan`（按卡/章节/行范围取施工图原文）、`expand_module`（深层结构下钻）、`project_index`（持久项目说明索引与交接覆盖）。界面合并同条件在途只读请求、切项目真正取消旧请求并阻止旧回包写入新项目，失败显示陈旧横幅＋原因＋最近成功时间。
- **私有事实（`.工作台/`）的显式备份与隔离恢复**：「项目信息」页里可按事件提交边界取一份一致备份（清单含格式与事件 schema 版本、截止提交序号、逐份内容哈希与证据清单；同一提交边界重复备份幂等），落点由你选且**必须在项目外**。恢复**只落在隔离目录**并逐项核验，塔台**不会自动替换当前数据**——替换与否由你本人决定。`.工作台/` 默认不进 Git，**被忽略或被提交都不等于已备份**。

### 1.1 MCP 工具面

一个 MCP 接口接入所有 Agent，走 **stdio**（Agent 客户端主动拉起）。工具数以 `src/mcp/tools/index.ts` 的注册表为唯一来源（`pnpm verify:v09-05` 对账）。当前 `main` 源码（Unreleased）共 28 个，现有 v0.2.0 Release 安装包尚未包含本轮新增能力：

| 类别 | 工具 |
| --- | --- |
| 项目与接续 | `list_projects`、`select_project`、`project_entry`、`doctor` |
| 任务与进度 | `list_tasks`、`report_task_status`、`update_progress`、`read_progress` |
| 认领与回执 | `claim_task`、`submit_task_result`、`rebind_task` |
| 执行与证据上报 | `report_execution`、`record_work_evidence` |
| 设计书与待议 | `read_design`、`append_discuss` |
| 施工图与结构 | `read_plan`（按卡/章节/行范围原读取材，未入账卡仍可读）、`expand_module`（深层结构下钻，稳定分页＋来源版本）、`project_index`（持久项目说明索引：`read`/`impact`/`coverage` 只读，`upsert`/`remove` 经唯一宿主） |
| 图纸与图 | `get_arch`、`get_project_graphs` |
| 图纸基线 | `manage_baseline`（`read`/`preserve`/`activate`，经唯一宿主） |
| 需求 / 变更 / 施工定义 | `manage_requirement`、`manage_change`、`import_plan_definitions` |
| 同步证据对账 | `register_sync_contract`、`scan_sync_evidence`、`read_sync_status` |
| 模型相关 | `ask_flash`（**会调用模型**，内部可写概念补全层，不是保证无副作用的只读工具） |

`claim_task` 的 op 面：claim/renew/release/**reopen**（reopen 是协调器专用的受控重开——已提交卡开新 attempt，旧 token 作废、旧结果永久保留，须带可取回的 `reopen_basis`；**不是新工具**，工具数不变）。

完整接入步骤与接续流程见 [`getting-started.md`](getting-started.md) 第 5 节与 [`agent-integration.md`](agent-integration.md)。

## 2. 六图的「当前实现 / 目标语义」口径（别混淆）

- **当前实现**：技术详情三张图（模块方框图／数据流向图／思维导图）**共用同一份静态 import 依赖层方向渲染**。它画的是**代码依赖方向**，**不证明业务或质量通过**，**不是业务数据流**。
- **目标语义**：数据流向图的目标是**业务/项目数据从输入源 → 处理节点 → 存储 → 输出/外部系统的实际路径**——逐条标「设计声明／代码静态分析／可复跑实测·未核实」，给稳定 ID、方向与验证态。**实体**＝输入源／处理／存储／输出·外部系统；**关系**＝数据的产生／传递／读写／转换；**静态 import 只作线索，不得生成「已验证」的数据边**。

数据流向图的**目标语义层已交付**（`get_arch` 的 v2 返回体与 `GET /api/projects/:id/arch/dataflow` 是同一份）：实体/关系分档、逐条出处（复算不过就剔除）、验证态（已验证／未核实／缺证）、一条**端到端数据链**（逐跳可点开追到出处与验证态）、**覆盖对账**（按设计源声明的数据输入/存储/输出**逐条**对账，缺路径显式报缺并阻断「项目可交付」结论）。**不新增任何运行时侵入采集**。

口径依据：`DESIGN.md` §3.2／§11.2；落地与复核见 `pnpm verify:v09-11`。

## 3. 需要 AI 服务的功能（与隐私/外发边界）

塔台本身**不需要任何模型服务就能用**。

| 功能 | 需要什么 | 不配置会怎样 |
| --- | --- | --- |
| 六图生成与下钻、任务账本、七步 Gate、MCP 工具、备份恢复 | **什么都不需要**（完全离线） | — |
| 模块"人话名"起名 | DeepSeek 兼容服务的 API Key（`DEEPSEEK_API_KEY` 环境变量，或 `<全局数据目录>/config.json` 的 `deepseek_api_key`） | 静态解析照常出图，模块名退回目录名，横幅说明 |
| 内置 AI 项目聊天、概念图补全、逆向设计草稿、`ask_flash` | 上面的 Key **＋一个可达的模型服务基址** | 功能不可用／报错；不影响账本与六图 |
| 逆向落稿的记忆检索（可选） | 本机已配置 brain-memory 记忆 MCP | 自动降级为「仅代码扫描」，界面如实标注，不阻塞起草 |

**只配 Key 不够**：默认基址 `http://127.0.0.1:3456` 是**作者本机的本地网关入口，普通用户机器上没有**。用你自己的兼容服务时，必须再设 `TATAI_DEEPSEEK_BASE_URL` 环境变量（或 `config.json` 的 `deepseek_base_url`）指向可达地址，并核对实际模型名。

**隐私边界（如实说明）**：项目文件、任务账本、六图等数据**都存在你本机**，静态解析等核心功能可完全离线使用；但启用聊天、模块起名等 AI 功能时，**发送给模型服务的内容**（相关代码片段、设计书段落、你的提问）会离开本机、到达**你配置的那个服务**。配置了第三方服务就按该服务的隐私条款执行。

## 4. 远程访问（保留的既有实现，默认关闭）

按现行设计，远程/手机端另列建设期，本轮不启用。默认启动只绑 `127.0.0.1`，零外部监听。另行启用局域网只读查看时（类 Unix shell）：

```bash
TATAI_REMOTE=1 TATAI_HOST="<本机局域网IP>" pnpm dev:server
# 只读查看上例即可；确需远程写时，逐字带上写开关与确认语：
TATAI_REMOTE=1 TATAI_HOST="<局域网 IP>" TATAI_REMOTE_WRITE=1 TATAI_REMOTE_WRITE_CONFIRM="我确认开启远程写模式" pnpm dev:server
```

- **远程默认只读**：上例不开写模式，写接口一律 403。聊天、终端、记忆这类**私人数据**默认不对远程下发，各有独立的显式开关。
- **访问要口令**：`pnpm remote:token show` 生成/查看，`rotate` 轮换；远程打开 `http://<主机 IP>:8787/` 输口令登录。
- **怎么关写模式（立刻失效）**：`pnpm remote:write off`——运行期关，不用重启。查状态用 `pnpm remote:write status`；每次翻转都在审计日志里留一条 `write-mode-on` / `write-mode-off`。
- **审计在哪**：`<全局数据目录>/logs/remote-audit.jsonl`（远程访问逐条留痕，含拒绝）。
- **不推荐公网直连**，四条理由：**无 TLS**（明文 HTTP）、**静态口令**（单 token 非多用户体系）、接口含 **PTY** 终端与文件写入（等于把本机 shell 挂上网）、响应含**私人数据**面。真要跨公网，套反代 + TLS，且反代必须对 SSE 关缓冲（nginx 写 `proxy_buffering off`），否则界面不刷新。
- **通配绑定逃生口（如实说明，别当成默认行为）**：另有一个显式环境变量 `TATAI_REMOTE_ALLOW_WILDCARD=1`，允许把服务绑到通配地址（`0.0.0.0` / `::`）——**默认拒绝**（不设它时绑通配地址直接拒启动）、**公网路径没有开关**（解析出公网地址一律拒），只有这个环境变量能放行，放行时日志打醒目 ⚠ 警告。该开关**已由用户 2026-09-24 裁定保留**，**远程仍默认关闭**；`pnpm verify:s1` ⑤ 对这个放行路径有断言（DESIGN.md §12.1-20、附录 G-5）。

## 5. 现在还不能用 / 如实限制

- **安装包只出 Windows**；WebView2 运行时与 node **都不随包**（装的时候由安装器联网拉微软官方引导器，运行时要 PATH 里有 node）。
- **没有自动更新**，升级靠覆盖安装（步骤与注意事项见 [`getting-started.md`](getting-started.md) 第 2 节）。
- **远程只读、默认关闭**，不提供"允许公网"的开关（局域网通配绑定另有一个**默认拒绝**的显式环境变量逃生口，见上一节）。
- **没有完整的自动接续与闭环**：当前不具备本链路的完整自动接续、图纸派生与审计证据闭环；中大型/超大型支持须经自举、故障与规模验证。本机单用户优先。
- **性能只是有条件样本**：2026-10-03 统一优化的读数是**一份冻结的真实项目镜像**（约 2146 文件、约 53 MB 事件账本、9200 事件、44 批次）上每种链路 30 个暖样本的中位值——真实 MCP 完整接续 p50 约 4709 ms → 1333 ms（约 3.5×），直接接续入口 p50 约 2736 ms → 872 ms（约 3.1×）。这是该镜像/该现场下的**有条件样本结论，不是普适倍数、也不是「全链路秒回」**：完整同步报告与新增证据写入仍有百毫秒级尖峰，拟议的暖界面 300 ms／轻接续 1 s／小证据 2 s 目标未全面达标；换项目规模与负载读数会不同。
- **已经运行中的 MCP 连接保留旧内存代码**：从当前源码构建并更新程序后，要让**当前会话**用上新的接续逻辑与 `read_plan`／`expand_module`／`project_index` 三个新工具，需重连塔台 MCP；新启动的连接使用配置路径下已更新的 `server/mcp.js`。程序更新完成不等于旧客户端内存已更新。
- **不会替你执行或验收**：塔台管理协作事实与执行请求，**不启动/终止 Agent 进程**（外部协调器负责），**不代替用户点 Gate**。MCP 提供工具不等于客户端必然主动调用；只读客户端按能力如实声明。
- **桌面壳退出的进程树收口**：壳正常关闭或强制结束时，由它启动/接管的后端子树会退出并释放端口（尤其 8787），且**只终止本壳的后端**、不误杀其他 Agent 客户端。**如实限制**：Job 建不出来时退回 `taskkill` 兜底（壳打告警，强杀仍可能留孤儿）；端口被**别的进程**占用时不自动杀占用者（弹窗说明＋给处置命令）。细口径见 [`../src-tauri/README.md`](../src-tauri/README.md)「进程树收口」。

## 6. 设计与施工方向

**典型协作流程（各环节用什么工具/模型完全由你决定，塔台不绑定任何品牌）**：任一会话与用户聊方向 → 设计角色（你本人，或你指定的高能力模型）审定设计书和施工图 → 塔台整理图关系并生成规划图 → 用户选定的执行 Agent 认领施工 → 低成本模型做审计/修复 → 关键节点独立终审 → 用户体验验收。角色与模型/客户端分开；这是**分工模板，不是自动启动命令**。

目标主界面提供项目图、设计书、施工图、聊天、实况与验收。内置 AI 语义整理（模型服务可配置）协助整理已审定图纸，**程序检查和绘制，不由模型猜完成度**。人类下一工具/模型/档位教学与一键启动向导延期；当前增加的 Git 版本提醒只做观察，不自动提交或推送。

**提交执行结果 ≠ 独立审计通过 ≠ 用户验收。** 逐卡状态与证据见 `PLAN.md`；范围、依赖与验收见 `DESIGN.md`。
