- 基线：主仓/备份/隔离工作树 28 个脏文件已独立复算 SHA256 一致。基线类型检查、六图 45、声明 40、简报 40、同步 98 项通过；简报真实快照体积段未测。
- P1：不能直接使用旧 resolveDesignRef 的 first-match 作为精确定位证明。当前实现会把附录缺失子节降到父节、把范围引用只取第一个编号；这不满足本轮精确取材。复用 materialSection 围栏感知解析和唯一完整标题判据，新增明确的严格解析入口，不改变旧蓝图解析语义。多个显式编号逐个解析；明确范围只有可证明完整展开时才 resolved，否则原引用 unresolved；缺失子节不得降父节，歧义不得取第一项。无 section 的 unresolved 条目去重必须包括 source_ref，不能丢失第二个失败引用。原文件指针可作为 trace_reference 保留。

- P2：源码实证 assertClaimSyncGate 只用于认领类事件，不是 task.result_submitted 的现行必经门禁。不得在草案中声称结果提交已有该门禁，也不因预检功能新增结果提交同步门禁。逐项核对真正适用于 result_submitted 的服务校验；不适用与未检查明确区分。当前五查含 token 前缀和幂等键错误文本，本轮共享预检输出必须完全隐藏 token；必要文案安全纠正允许，不必逐字保留泄露。预检不证明测试真正执行或覆盖完整，引用存在与内容验证分开。
- P3：契约登记者不是所有修复项的责任人。报告 registered_by 与 recommended_role 分开，后者按失败类型建议协调/执行/审计职责，不替人授权。修复计划只列来源漂移不能自动刷新。候选为明确未验证的草稿；若仅返回 JSON，不新增保存入口。确认候选进入现有正式扫描时必须实核候选输入版本，不能只有注释要求。
