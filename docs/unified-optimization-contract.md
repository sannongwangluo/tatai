# 统一提速与按需接续契约（2026-10-03）

依据：用户已要求「现在就根据方案对塔台进行优化」；DESIGN §6.8 为正式设计入口。本文细化共享事实、增量读取与 AOCI 借鉴的实现契约。此前 06/07 候选方案是来源，正式施工以 DESIGN、本契约及 PLAN V09-30…V09-39 为准。实现与验证状态独立记录，不能将文档目标当已上线。

## U1 同版事实与版本边界

入口、图摘要及同步核验中的相同输入只求值一次。请求上下文由服务建立，禁止客户端传入任意 events 或 passed 报告获得放行。账本快照包含可验证内容版本；独立设计/施工图、基线、任务映射、证据源清单、规则版本纳入依赖。宿主报告与本地材料不同版时不拼接通过；有界重试后返回明确过期或失败。

不得将 mtime/size/seq、监听或 TTL 当作内容未变证明。缓存需要实际内容核验；外部保留长度及 mtime 的改写必须被识别。图的旧 graphInputSha 尚未证明覆盖完整依赖，不直接用于跨请求全图复用。写口锁内仍核对当前事实及权限，历史展示不解锁任务。

## U2 事件读取与持久增量

先共享一次 loadEvents，覆盖任务、认领、执行、审计与投影；独立 decisions.jsonl 不伪装成同一账本。可按实际内容哈希复用解析，完整校验历史前缀后只解析新增后缀；保持流式读取约束和缓存内存上限，不为大文件无界存储原字节。

持久投影复用既有可重建 state.json 权威关系，新增派生缓存只允许由事实重建，不可独立编辑业务状态。记录格式版本、完整输入指纹、应用边界和校验信息；候选增量结果先与全量算法比对。缺失、损坏、截断、替换、中段改写、半尾、schema/规则变更或信任不明时回退全量或如实报错，不能用旧绿色结果顶替。

实测收敛（2026-10-03）：冻结9200事件/53MB账本的全量 buildSnapshot 暖p50为1.07ms、p95为1.42ms，原读取解析p50约277ms。当前必需提速实现为请求共享、经内容核验的进程内解析/前缀增量与后台派生；跨重启持久快照加速转为条件项，仅在冷启动剖析证明折叠成为显著瓶颈且有可信完整校验时启用。现有 state.json 的可重建关系保留；磁盘快照核验原语不能被宣称为加速，也不得默认启用未经实体核验的复用。依据：统一证据根 baseline-fold-profile.json、review-probes/snapshot-tamper.json。

## U3 只读取材与交接

- read_plan 与 read_design 同一原文切片机制，支持卡号、索引、章节和行范围；区分 PLAN 定义存在、未入账、正文缺失；返回来源版本及可校验范围。
- MCP 续读入口验证完整来源哈希。旧短哈希游标仅定位，不能证明完整一致；无法证明时明确失效和重取。进程内包寿命如实标明，重启不得返回空包成功。
- expand_module 复用 expand 业务逻辑，提供子级、内外依赖、稳定分页、预算/忽略说明与来源；中间联接点和最终路径均防逃逸。静态依赖不是业务数据流。
- 前置说明来自已有 EntryFacts，仅解释基线/需求/卡/执行缺口，不新增 blocking，不改既有 next_action 判据。获授权设计角色可以登记需求/技术基线，不代签用户 Gate。
- 旧完整 project_entry 默认契约保持。轻量选项如新增，明确字段省略、来源版本和补取入口；必要核验照常完成。

## U4 UI 共享与后台派生

同项目、权限、参数和版本的在途请求合并。保持周期对账、回前台补拉、事件通知及隐藏页策略。切项目后旧结果不得回写；刷新失败保留旧值并明确陈旧，不伪装成功。

以剖析确定的 CPU 重派生为工作线程边界；工作者不能写业务账本。唯一宿主发布前比较输入版本，取消或过期代际不发布。队列有并发、积压和资源上限，多项目公平，无限通知不能让早先一轮永久等待。对正在阻塞当前任务的必要核验给予有界优先机会，但不得饿死其他项目；原有 graph_full 必需判据不删除。停止只收回自己拥有的工作者，不动外部 Agent。

verified_for_version 表示已验证特定版本；stale/rebuilding 可展示旧结果；failed/unknown 明确原因。写口只能使用当前复核通过的依据。健康/进度轻读应不被重派生占住事件循环。

## U5 持久项目说明、影响清单与覆盖

复用现有文档/蓝图/证据载体，由 Agent 维护受管文件或模块的职责、关系、接口、约束、来源文件及完整哈希；结构化索引是可重建导航，不是新设计权威。采用显式 schema、稳定身份、范围上限和原子更新；文件移动/删除、相关源变化、错误哈希、重复身份与未知字段必须有明确处理。只更新受影响条目，无关改动不重写全库；不要求首次全仓说明建完才继续开发。

提供按路径/任务取相关条目、查看陈旧/缺失项及原文入口。影响清单从已声明关系与既有映射产生，区分代码引用、Agent 声明与已验证关系，并关联已有测试/证据；未声明不能推断成无影响。必要源码核验仍由 Agent 完成。

交接清单列必需材料、实际返回范围/版本、遗漏及补取入口。送达不等于理解或验收；不新增形式性用户批准。文档/配置/数据库迁移文件可作为来源，凭据与业务数据不索引。直连数据库采集、自动推断业务数据流、另建第七张图及跨进程永久上下文包不在当前必需范围，沿候选方案条件启用。

### U5.1 载体与维护入口

项目根内 `docs/project-notes.json` 是 Agent 编写的版本化说明文档，属于待审说明层，不是设计、事件或验收事实。不存在时允许空索引，不能据此推断没有影响。每个条目含稳定 id、职责、接口、约束、有限来源路径及完整 SHA256、任务引用、关系声明和测试/证据引用。衍生检索视图按当前文件内容重建，来源不符立即标陈旧/缺失/未知；关系没有独立证据时只标 Agent 声明，不自动晋升为已验证。

`project_index` 的 read/impact/coverage 只读；upsert/remove 经唯一宿主，用完整文档版本做 CAS、锁内核对所有权与来源后原子写说明文档。写操作只维护指定条目，不重写其他条目语义；未知字段、重复身份、超预算和项目根逃逸明确拒绝。删除条目是删除说明，不能删除源文件或业务证据。路径迁移由保持 id 的显式 upsert 处理，不凭同名猜测。项目有同名但非本 schema 的文档时明确冲突，不能覆盖。

该入口与现有设计、图纸、证据入口互相引用；不新增颜色或用户 Gate。交接覆盖只能证明本次实际交付的材料范围；索引清单未取原文的部分记为未覆盖，并给出补取入口。

## U6 验收与发布

首先校准解析/读取字节/哈希/构图计数，避免文件 API 包装双计数；记录 MCP/HTTP、排队、计算、序列化、浏览器耗时。基线冻结，真实数据只读，压力与故障测试使用隔离数据。

拟议目标：暖界面 300ms 可见有效摘要或明确更新状态，暖轻读及忙时健康/进度 p95 200ms，无变化版本轻接续 1s，基线小范围证据跟进 2s。均待实测，不用旧缓存/空骨架/跳过门禁制造达标；冷启动和完整结果另报。暖至少30样本，冷至少5次；报告原始样本、p50/p95/max、错误/失效及资源。达不到报告差距，不静默改预算。

验收覆盖：打开/切项目/看图；取卡/续读/交接；提交证据后继续；多客户端与锁等待时源变；重启、损坏和半尾；同长度mtime改写、漏通知及路径逃逸；多项目忙时公平与停止。新旧全量语义一致，时间等非语义排除项逐项列明。

不覆盖原24项未提交现场；修改前后留内容指纹。本轮登记采用当前真实接口；塔台自身未在生产注册表时不伪造成功领取或导入历史，先落真实施工/证据记录，隔离自举验证不等于生产正式提交。

部署由本会话统一负责，完整构建、绑定、备份、校验后切换；保持已获授权的连续执行。不得覆盖运行期新增业务事件。验收报告分别记录作者、非作者复核、发布与用户验收。
