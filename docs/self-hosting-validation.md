# 自举验收：空案例说明（公开）

> 本文是**公开文档**：不含任何私人路径、真实项目名、真实证据正文或执行产物。
> 塔台自己的真实自举记录、截图与执行产物只落 `.工作台/evidence/`（默认 gitignore，不外泄）。
> 验收依据是 DESIGN §1.6 / §3.14 / §11.8 与 PLAN 的 V06-13 卡；本文只说明"怎么跑、看什么、边界在哪"。

## 1. 什么是"自举验收"，为什么它必须分两半

塔台管理的第一项目是它自己（DESIGN §2.1「自举」）。所以它的验收不能只看代码或单测，
要走两条真实链路（V06-13 检查项 ① / ②）：

1. **隔离演练**：在一个空目录夹具里，从"只有一份已审定的设计书与施工图"起步，走一遍
   「灰图 → 图纸改动 → 聊天与任务关联 → 双执行者认领 → 旧证据失效 → Git 提醒」；
2. **一项真实变更贯穿全链**：拿本项目自己**范围内尚需完成**的一个真实修复项，走
   「讨论 → 图纸 → 规划图 → worker 施工 → 独立审计 → 抽查 → 落地 → 复测」。

**两半都必须"自动通过"与"用户本人验收"分开记**。自动脚本能证明的是"链路按契约走通了"；
它**不能**代替人去看一眼、点一下、判断"这体验我接受"。
按卡面：自动部分过了但用户还没验收时，这张卡保持 `doing/blocked` 并写明原因——**Agent 不代签完成**。

## 2. 怎么跑（两条命令，都可复跑）

```bash
pnpm verify:v06-13          # 隔离演练（Node/tsx，自带夹具，不联真模型、不花钱）
pnpm verify:v06-13-ui       # 浏览器验收（Python + Playwright，真 DOM / 真 HTTP / 真文件系统）
```

两条都自带隔离环境：临时 `TATAI_HOME`（`os.tmpdir()` 下）+ 临时夹具项目，**不碰任何真实项目的
`.工作台/`**；跑完自删（想留现场：`TATAI_KEEP_TMP=1` / `V0613_KEEP_TMP=1`）。
浏览器脚本默认把截图写进 `.工作台/evidence/V06-13/1/screenshots/`（可用 `V0613_SHOT_DIR` 改）。

判据是**逐条断言名 + 计数 + 退出码**，不是截图数量、也不是某个总分：

- 脚本里每条断言打 `PASS/FAIL` 与一句人能读懂的话；
- 末尾打 `合计 PASS n / FAIL m`，**有 FAIL 就 `exit 1`**；
- 截图是"人来看"的入口，不构成通过依据。

## 3. 浏览器侧必须演练的 10 条（DESIGN §3.14 原清单 → 断言落在哪）

| §3.14 原话 | 脚本里的落点（断言组） |
| --- | --- |
| 空仓库有灰色规划图 | ② 空仓夹具：能出图、节点状态只允许"未映射/已规划"、**一个绿都没有**、灰带文字通道 |
| 设计与施工图可互相定位 | ③ 图节点详情给出设计书章节出处 / 施工卡出处；关系层有 `task_design_ref`；施工图页卡片↔原文双向定位、带行号 |
| 同一任务在聊天、图和施工图显示同源状态 | ④ 施工图给执行状态、图给六态、聊天动作指向同一 `task:` 稳定 id，且两处都与服务端投影对得上 |
| 切项目不串消息 | ⑤ 甲项目里没有乙项目的消息/会话，反之亦然 |
| 刷新不丢草稿与动作回执 | ⑥ 输入框草稿刷新后还在；动作回执来自落盘日志、刷新后逐条还在 |
| 未知不显示成功 | ⑦ 全部待验收项是 `pending`；没有"用户已接受"这类措辞；验证过了但人工验收仍待给 |
| 旧证据失效后不继续显示已验证 | ⑧ 源修订一变，旧证据不再算有效、图节点不再是已验证；旧结论保留在历史里；**只影响受影响对象** |
| 纯后端场景可读 | ⑨ 纯后端项目给出"输入/期望/实际/证据"四段可读场景 |
| 终端不出现在主导航 | ① 主导航恰为五页；终端只在辅助入口（维护诊断） |
| Git 提醒不误报已备份 | ⑩ 提醒的私有事实备份状态只有"未知"，并说明"无法由 Git 推断"；不出现"已经备份/已同步" |

另有 §3.14 第一句「人应能不看代码地指出目标、当前改动、可体验结果、未验证范围和需要自己判断的事情」→
⑪：工作面的状态条给出当前项目/当前目标/有效版本；图上详情给出验证结果与**未覆盖范围**与出处。

## 4. Node 侧隔离演练的八段（V06-13 检查项 ①）

| 段 | 演练什么 | 关键判据（节选） |
| --- | --- | --- |
| ① 空仓灰图 | 零代码 + 零执行也能出规划图 | 图发布成功、代码覆盖 0、派生**零模型**、节点/关系里没有完成色字段、所有对象 `not_started` 且无一个绿 |
| ② 逆向入口两份草稿 | 老项目先出设计草稿 + 剩余施工草稿，审定后激活配套基线 | 两份草稿都落盘、起草**不动 Gate**、施工草稿把已有实现标"待验证"、审定后可激活、**无验证证据的实现仍待验证** |
| ③ 图纸改动 | 半套图纸不生效；新基线成功前旧基线继续有效 | 只改一份/坏施工图 → 拒绝且基线流水一条不增；配对齐全才新增一条并记 `supersedes` |
| ④ 聊天与任务关联 | 聊天动作认得出、落在同一份事实 | 动作 `affected_ids` 指向同一个任务 id；同一句话重复发送幂等；一次不满只登记成本地问题 |
| ⑤ 双 Agent 认领 | 冲突与放行都要明确 | 第二个持有者被拒并给当前版本与重读入口；依赖未释放不放行；无证据的"完成"不收；别人的 token 不认；租约到期没核实依据不重派 |
| ⑥ 旧证据失效 | 旧绿转待验证、旧结论进历史 | `freshness=verification_stale`、`display!=verified`、历史里有旧结论、显式声明受影响范围时只重验它 |
| ⑦ Git 提醒 | 只读、不误报 | 探测前后 HEAD/索引/工作树逐项相同；无上游不写"已同步"；代码提交 ≠ `.工作台/` 已备份 |
| ⑧ 收尾自证 | 本脚本没动不该动的东西 | 根文档首尾哈希一致；既有 `scripts/**` 首尾哈希一致；脚本源码里没有真实项目路径；夹具全在临时目录 |

## 5. 真实变更全链的最小做法（可照抄的"空案例"）

不为了演示新增任何产品功能——**从自己账上挂着的既有红里选一个**（本文不列具体项，各项目自己登记）。
链路与留证：

1. **讨论/定方向**：写清用户原意（引用既有的 PLAN/PROGRESS 登记）、技术定位与**允许范围**；
2. **图纸**：一页设计依据 + 一张施工卡（卡号/交付目标/依赖/完成证据/验收检查项）；
   **审定角色如实标注**（谁以什么身份审的；不是设计角色就写"技术判断代行"，不是用户就写"待用户拍板"）；
3. **规划图**：由已审定图纸**派生**（零模型），留节点/关系/覆盖账目与"发布/未发布 + 原因"；
4. **worker 施工**：在一个**隔离副本**里让执行 Agent（本项目是 Kimi Code + DeepSeek V4.1 Flash）干活。
   **绝不让 worker 直接改工作树**：副本里产出 diff → 人/协调者审查 → 才落地；
5. **低成本独立审计/修复**：另起一个**没有上文**的会话（或独立脚本）做检查，**不许作者给自己盖章**；
6. **抽查**：读原文抽查关键风险与"没报错的范围"，抽查发现系统性遗漏就扩大同类验证；
7. **落地与复测**：把审查过的 diff 落到真仓库，跑相关验证（转绿/转红的**前后对照**都要留）；
8. **换执行者接续**：关掉旧会话，起一个**没有上文**的新执行者，只给项目入口规则与交接资料，
   记录它**补问了几次、有没有重复劳动**——需要用户逐任务复述就不算通过；
9. **用户本人验收**：留空并写明"等待用户操作"，给出"看什么、点哪里、判定什么"的清单。

## 6. 边界与不做的事

- 自动脚本**不能**证明"体验好"，也**不能**代替用户 Gate；`done` 只表示这张卡的执行结果已交付。
- 隔离演练**不能**证明大规模项目的适用性（那属规模与恢复的另一张卡）。
- 模型/worker 的"通过"不是验收：最终结论要能回到**原文、证据哈希与最小可复跑的判据**。
- 无人接手、无用户验收时，如实写"等待"，不写"已完成"。
