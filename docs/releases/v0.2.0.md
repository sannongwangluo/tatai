塔台 v0.2.0（2026-09-30）—— 图读取全量可查看 + 同步证据对账版。**相比 v0.1.1 有功能性新增与接口面变化。**

## 新增了什么（以下均已交付代码与服务；逐卡独立审计与用户验收随项目整体进行）

### 1. 六图全量可查看

- 概览保持原有的防爆炸上限不变（主视图 5–15 分组、技术层 15 节点/40 边、单枝 40 子级），**每个聚合点新增「显示全部／加载全部子级」入口**；技术详情画布支持按名称/id/路径**搜索定位**并居中。
- **MCP `get_project_graphs` 增加 `mode=full`**：取回概览聚合隐藏的节点/关系——未聚合并集、按 **4000 对象/页同一快照分页续取**；`complete` 只表示本次请求对象取完，不等于源码全覆盖。
- 新增**逐项取回**路径：`GET /api/projects/:id/arch/items`（未聚合并集分页检索）＋ UI「查看被聚合对象」抽屉；`/arch/expand` 支持 `childrenOffset` 稳定分页。
- 游标四段制绑定读取模式（overview↔full 跨模式明确拒绝）。

### 2. 阶段接续与阻塞卡门禁

- `project_entry` 的 `required_reads` 支持项目自带的 `.工作台/work/stage-reads.json`（**机器派生指针**、可选，不是新设计也不是授权源）：合法则把本阶段必读原文与 `preferred_task_id`（只在真实就绪候选内生效）一并给出。
- 指针损坏、来源文件缺失或内容漂移（sha256 不符）一律 `next_action=blocked`，**不静默派活**；文件不存在时行为与旧版完全一致（老项目零影响）。
- 任务状态为 `blocked` 的卡不再允许**新领**：MCP `claim_task` 与直连写入服务（`POST /api/work/command`）两条入口都拒并引 `blocked_reason`；解阻只能由协调器按原启动条件写回 `ready`。续约/取消/已交付语义不变。

### 3. 同步证据自动发现与完整性对账

- 执行前经 `register_sync_contract` 登记「应同步清单」契约（限设计/协调职责；来源哈希实核、同批次改内容拒、`supersedes` 不得减少旧必需项或把 `blocks_entry` 改 false）。
- 完成后把 `<batch_id>.evidence.json` 证据包写进项目 `.工作台/work/sync-inbox/`；塔台**后台自动发现**（唯一写服务宿主发布描述符后启动，未被 UI 选中也发现，注册表增量发现新项目）并逐项读取**当前实际目标**验收（文件字节 / JSON 值 / 账本折叠 / plan 解析 / 六图 canonical builder / stage-reads）。
- 只读 `GET /api/projects/:id/sync-status` 与 MCP `read_sync_status` 同判据；`scan_sync_evidence` 显式扫描与后台共用同一逻辑与写口。`blocks_entry` 批次未当前通过时 `project_entry` 给 `sync_summary` 且 `next_action=blocked`，`claim_task` 与直连写口同样拒绝；**补证后自动解阻，不需人工逐项放行**。
- **通过只表示所登记范围在该版本对账通过**，不等于业务实现、独立审计或用户 Gate。契约细节见 [`../sync-evidence-contract.md`](../sync-evidence-contract.md)。
