> 面向用户的变化见 [`../../CHANGELOG.md`](../../CHANGELOG.md)。

塔台 v0.3.0（2026-10-04）—— **界面与品牌统一 + 接续提速版**。**相比 v0.2.0 有功能性新增、界面变化与接口面变化。**

## 新增了什么（以下均已交付代码与服务；逐卡独立审计与用户验收随项目整体进行）

### 1. 界面与品牌统一

- **唯一品牌形状**：采用线条小塔台作为界面标志的**唯一 SVG 形状**（`viewBox 0 0 28 32`，圆端圆角、无填充）；界面标志、网页图标、Windows EXE／安装包图标与桌面快捷方式**同源生成**，桌面图标用对浅／深底都清晰的底板。
- **亮／夜主题**：默认**浅色**（浅灰纸面、墨色文字、蓝色选中态），左下角可切**夜间**（深墨绿灰背景、浅文字）；选择**本机记住**（刷新／重开保留），Windows 原生标题栏随之同步切换；外观存储不可用时不白屏。
- **人话读图**：项目图**先讲用途、当前情况与关联**，再展开来源与技术详情；默认大白话标题与状态，技术 ID／类型／成员折叠可查；**已有描述标明出处，缺少用途或设计理由明确写「尚未记录」，不按文件名编造**。
- **对象带入聊天草稿**：选中方块可把**真实项目、对象与来源**追加到聊天草稿，**保留原文、可编辑**，由你确认后发送。
- 保留**五主导航**（项目图／设计书／施工图／聊天／实况与验收）与**六图**、证据状态判据、项目切换隔离；状态不只靠颜色、同时用文字表达。集中修复浅色半透明语义文字低对比、技术长说明挤压画布、首次定位被取消的问题；状态判据、账本与项目隔离不变。

### 2. 按需接续与统一提速

- 取接续时**一次请求内共享同一份账本快照与派生事实**（不再重复读盘、不跨请求缓存旧绿）；只读重计算移到**进程内有界工作池**（有界排队、取消、多项目公平），写仍只经唯一写入宿主。
- 文件读取做**内容校验 + 前缀增量**：识别同长度改写／保留 mtime／截断／中段坏行，**不以 size/mtime/TTL 充当内容身份**。
- 界面**合并同条件在途只读请求、切项目真正取消旧请求**并阻止旧回包写入新项目，失败显示陈旧横幅＋原因＋最近成功时间。
- **性能读数是该冻结镜像／该现场下的有条件样本（30 个暖样本的 p50），不是普适倍数**；逐条问题、修复、实测中位改善与**如实列出的一项变慢**（扫描幂等单次 3159 ms → 3588 ms）见 [`../../CHANGELOG.md`](../../CHANGELOG.md)。

### 3. 三个按需取料工具

- **`read_plan`**：按**卡号／章节／行范围**取施工图原文，免「整本读取」，未入账卡仍可读，返回来源版本与可校验范围。
- **`expand_module`**：Agent 直接指定模块取得子级、内外依赖、稳定分页与预算／忽略声明；中间联接点与最终路径都防目录逃逸。
- **`project_index`**：维护 `docs/project-notes.json`（职责、接口、来源、关系、影响与交接覆盖），`read`/`impact`/`coverage` 只读、`upsert`/`remove` 经唯一宿主。**这是要 Agent 持续维护的说明索引：不存在时如实返回空，不会自动扫描全仓生成**；声明关系不冒充验证事实。

### 4. 正向流程与证据链补齐（2026-10-02 批次，随本版发布）

- **正向成套图纸直接激活（F1）**：已有 DESIGN/PLAN 可保存为不可变历史并做技术审定激活（零差异即可，固定 `delegated_technical_review`，须带两份源的当前内容哈希与审定依据，**不调模型、不写用户 Gate**）。
- **可见工作面统一自动刷新（F2）**：页面每约 5 秒自动重取，回前台与网络恢复触发；切项目丢弃旧响应并保留各项目输入。
- **Agent 阶段 / 执行 / 证据上报链（F3）**：`report_execution`（执行回执／心跳／检查点／停止／失败）与 `record_work_evidence`（证据正文、成果登记、自检、独立审计、修复、复测与缺陷），重试幂等；**心跳缺失不等于停机**，只有带确认依据的 `stopped` 才算已停。
- **当前代码证据有效性核验（F4）**：用于「已验证」的检查绑定**有限、项目内、可取回**的源码清单；被覆盖文件变化／删除／不可读即失效或转待复核。
- **完整正向 / 返工 / 恢复旅程（F5）**：真实 stdio MCP 与 HTTP 全流程已在隔离夹具跑通（含阻塞与恢复、返工、新 attempt、证据／独审／复测、新客户端接续）。

## 升级建议（从旧版覆盖安装）

- 装新版＝从 [Releases](https://github.com/sannongwangluo/tatai/releases) 下一个新包**覆盖安装**，没有自动更新。
- **升级前先正常退出塔台**：关窗即会带走它启动的后端并释放 8787 端口。若安装器仍提示进程占用，再按排错确认残留，**不要无差别结束 node 进程**（别的 Agent 客户端可能正用着它）。
- **升级前建议先备份两处**：全局数据目录（`~/.tatai` 或你的 `TATAI_HOME`）与每个被纳管项目根下的 `.工作台/`。覆盖安装与卸载都**不删用户数据**（数据不在安装目录里，安装目录运行期只读）。
- **旧 MCP 连接需重连**：升级到 v0.3.0 后，要让**当前会话**用上新的接续逻辑与新增工具，需重连塔台 MCP；新启动的连接使用已更新的 `server/mcp.js`，运行中的旧 MCP 进程保留旧内存代码。
- 本版**未变更锁文件**（`pnpm-lock.yaml` 未动）。

版本串（`package.json` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.toml` / `src-tauri/Cargo.lock` 根包 / MCP 握手 / 界面页脚）本版统一为 **0.3.0**；运行时版本取自单一来源 `src/shared/version.ts`（构建期内联，产物运行时不读文件），各处一致性由 `scripts/verify-version-consistency.ts` 对账。
