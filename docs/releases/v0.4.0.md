塔台 v0.4.0（2026-10-09）—— **默认交付总览 + 功能清单与接续取证版**。**相比 v0.3.0 有功能性新增、接口面变化；界面结构与数据格式向后兼容。**

## 新增了什么（以下均已交付代码与服务；逐卡独立审计与用户验收随项目整体进行）

### 1. 默认交付总览（V09-62）

- 人的**默认入口**从六图换成**交付总览**：一页核对本期功能、需求依据、技术验证、非作者审查、未解决问题和运行版本，详细检查与证据按需展开。
- 只有**完整功能范围核查、功能验证、独立审查与运行版本核对都具备当前有效证据**，页面才显示「可以开始人工试用」；缺证据、范围未定、旧版本或读取失败会逐条点名。**技术就绪不等于你已接受——塔台不代你签收验收。**
- 六图**保留用于查结构与定位问题**，但章节方块的颜色**不再充当整项目交付结论**。
- `feature_ledger.delivery`（含 `integration` 组合流程验证）与逐项 `agent_review` 为**同源只读扩展**；旧宿主缺字段应报未知，不拿其它绿状态代替；证据仍经既有唯一写口，**不新增完成台账**。

### 2. 功能清单与四维读数（V09-51…V09-58）

- 设计书旁的人话**功能清单**：设计覆盖／实现／验证／用户接受**分开显示**（四维读数），绿只取验证读数。
- 同一判据的**只读**读口：HTTP `GET /api/projects/:id/feature-ledger` 与 MCP `feature_ledger`——**只读派生，不建第二张进度台账**；`paging.complete` 与 `coverage.source_complete` 分开。**读到清单不等于已通过**（引用存在 ≠ 已核对、子项都绿不冒充组合功能通过）。
- 逐项**工作包**与 check 级交接（已知参数／缺参／下一步动作），两种接续模式。

### 3. 接续取材更省、更准（V09-41…V09-44、V09-46）

- **`task_brief`**：`project_entry` 的紧凑只读简报——默认理由索引／短摘要，保留动作与当前任务约束、必读与图简状态，完整理由按版本补取（`detail=full` 兼容旧文）。
- **阶段材料按任务精确取材**：条目带 `purpose` 分类（`required_content` 先读正文／`trace_reference` 按需回读／`resume_context` 续接现场）；设计引用派生条目带 `resolution`／`source_ref`，定位到**当前版本**的章节与派生行范围（认不出即 `unresolved`＋原始引用＋补取入口，**不是已读、不是已通过**）。

### 4. 提交前只读预检与同步修复计划（V09-47、V09-48）

- **`preflight_task_result`**（新）：与 `submit_task_result` **同形输入**、共用同一份判据——提交前**一次列清**可预判缺项与**锁内未查项**（`not_checked` 与 `not_applicable` 分开表达）。**明确只读**：不写事件／证据／租约、不自愈、不产生认领；**不是门禁、不是通行票**——预检到提交之间版本／认领可能变化，提交时在唯一写入服务临界区内**重核**。旧宿主不支持该只读路由 ⇒ `UNSUPPORTED_BY_HOST`，**绝不回退**到提交路由。
- **同步只读修复计划**：`read_sync_status`／`project_entry` 给现行批次的逐项修复计划（原因／责任角色／代次／下一读取入口）；默认简报里是紧凑导航，`detail=full` 与 `read_sync_status` 完整保留。

### 5. 运行部件构建身份（V09-45）

- 构建期把身份（`release_id`／`build_id`、server／ui 两组输入指纹、工具链）**烙进产物**；活进程返回**启动时载入**的常量（不按请求读盘冒充）。
- `GET /health`、`GET /api/work/health` 与 MCP `doctor` 带 `build_identity`，界面诊断显示自身身份与偏斜对照（`same_release`／`skew`／`unknown`；旧包未内嵌一律**未知态**，**不判一致**）。
- **发布验收要求**：前端／随包后端／壳／安装器必须重建，并在受控安装后**实际读回**——安装运行实例报出的身份须与本次构建一致，**未安装不得写通过**；回滚包随发布保留。

### 6. 解析热路径等价优化（V09-50）

- 真实绑定下源码依赖采集走**原生 tree-sitter query**（非静默回退）；合成夹具逐文件对账，行为等价。

## 升级建议（从旧版覆盖安装）

- 装新版＝从 [Releases](https://github.com/sannongwangluo/tatai/releases) 下一个新包**覆盖安装**，没有自动更新。
- **升级前先正常退出塔台**：关窗即会带走它启动的后端并释放 8787 端口。若安装器仍提示进程占用，再按排错确认残留，**不要无差别结束 node 进程**（别的 Agent 客户端可能正用着它）。
- **升级前建议先备份两处**：全局数据目录（`~/.tatai` 或你的 `TATAI_HOME`）与每个被纳管项目根下的 `.工作台/`。覆盖安装与卸载都**不删用户数据**（数据不在安装目录里，安装目录运行期只读）。
- **旧 MCP 连接需重连**：升级到 v0.4.0 后，要让**当前会话**用上新的接续逻辑与新增工具（`task_brief`／`preflight_task_result`／`feature_ledger`），需重连塔台 MCP；新启动的连接使用已更新的 `server/mcp.js`，运行中的旧 MCP 进程保留旧内存代码。
- 本版**未变更锁文件**（`pnpm-lock.yaml` 未动）。

版本串（`package.json` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.toml` / `src-tauri/Cargo.lock` 根包 / MCP 握手 / 界面页脚）本版统一为 **0.4.0**；运行时版本取自单一来源 `src/shared/version.ts`（构建期内联，产物运行时不读文件），各处一致性由 `scripts/verify-version-consistency.ts` 对账。
