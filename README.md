# 塔台 Tatai

> 让一个人与多个 Agent 持续推进同一个项目。

塔台面向用 Agent 开发项目的非程序员：保存意图、设计书、施工安排、进度和验收证据，让换模型、换会话后的 Agent 有依据接着做。当前以作者自用为先，作者自行选择工具、模型和档位。

## 它解决什么问题

用 Agent 做项目的人，迟早撞上四件事：

1. **换模型／换会话就"失忆"**——上个会话聊定的方向、做过的决定，新会话一概不知，一切从头解释；
2. **多个 Agent 各干各的**——这家改的、那家改的没有同一份事实，互相覆盖、互相打架；
3. **"做完了"说不清**——谁说的做完、凭什么算做完、验证证据在哪，翻聊天记录对不上账；
4. **改一处不知道影响哪**——文档或代码动了一行，哪些东西要重新验证没人说得清，要么全量重验、要么漏验。

塔台把这四件事变成**一份可追溯的账**：意图、设计书、施工图、任务、进度、验证证据全部落成事件流，Agent 通过 MCP 接进来读写同一份事实；状态只来自事实与有效证据，谁也不能口头宣布"完成"。

## 核心能力

- **一个 MCP 接口接入所有 agent**（19 个 stdio 工具：项目接续、任务认领/回报、六图读取、Flash 问答等）
- **六图**：功能全景／系统架构／施工依赖／模块方框图／数据流向图／思维导图，逐对象带来源与证据标注，可下钻追到出处
- **七步 Gate 与事件账本**：任务由 Agent 自报、Gate 由用户确认；状态不涂色、不编绿
- **证据分段失效**：改一份文档只重验受影响的对象（单卡／章节粒度），不再"动一行、全图重验"
- **私有事实显式备份与隔离恢复**（`.工作台/` 按事件边界备份，恢复只落隔离目录、不自动覆盖）
- **Tauri 2 桌面应用 + 本地服务**：数据全在本机，不依赖云服务

## 现在可以使用什么

- 项目登记、目录接入与跨项目概览；七步 Gate 由用户确认，任务由 Agent 自报。
- 模块方框图、数据流向图、思维导图和下钻。**这三张「技术详情」图当前共用同一份静态 import 依赖层方向渲染，这是「当前实现」**：它画的是代码依赖方向，不证明业务或质量通过，**不是业务数据流**；其中**数据流向图的目标**是业务/项目数据从输入源 → 处理节点 → 存储 → 输出/外部系统的实际路径（**逐条标「设计声明／代码静态分析／可复跑实测·未核实」**，并给稳定 ID、方向与验证态；**实体**＝输入源／处理／存储／输出·外部系统，**关系**＝数据的产生／传递／读写／转换；**静态 import 只作线索，不得生成「已验证」的数据边**）。**当前并未实现真数据流**——不得把上面那层静态依赖渲染当成业务数据流（DESIGN §3.2／§11.2；目标语义那一层已落地，见下一条）。
- 设计书展示与显式追加落稿、内置 AI 项目聊天（模型服务可配置）、概念图补全、逆向设计草稿。
- 流程实况、文件变更、终端与 Tauri 桌面壳。终端仍在当前软件中，已移出用户主导航、收进辅助入口的「维护诊断」。
- 数据流向图的**目标语义层**（已交付）：在「技术详情 → 数据流向图」页签里，画布上方**同时**给出两句话并互相区分——「**当前实现＝三张技术图共用的静态 import 依赖层方向渲染**（不是业务数据流）」与「**目标语义＝业务/项目数据从输入源 → 处理节点 → 存储 → 输出/外部系统的实际路径**」。目标语义那一层按项目派生（`get_arch` 的 v2 返回体与 `GET /api/projects/:id/arch/dataflow` 是同一份）：实体分输入源／处理节点／存储／输出·外部系统，关系分产生／传递／读写／转换，每条带稳定 ID、方向、逐条出处（设计声明／代码静态分析／可复跑实测，归不进三档标「未核实」）与验证态（已验证／未核实／缺证），并给出一条**端到端数据链**（逐跳可点开追到出处与验证态）与**覆盖对账**（按设计源声明的数据输入/存储/输出**逐条**对账，缺路径显式报缺并阻断「项目可交付」结论）。出处一律按「文件在＋章节在＋定位片段原样出现」**复算**，复算不过就剔除并按实剔除后的证据重判验证态；静态 import 线索只进 `static_clues`，永不计入出处档位。**不新增任何运行时侵入采集**。**2026-09-25 复核批次补记**：`.工作台/intent.json` 的来源读点已补齐（新增 `src/server/work/intent.ts`，登记/更新与唯一写入服务边界同一判据、悬空即拒），真实项目覆盖对账实测 **声明 24 条 / 覆盖 23 条＋未引入 1（SQLite 备选缓存，设计明文缓期，不计覆盖也不计缺）/ 缺路径 0**；此前「缺路径 1 并阻断交付」的读数为历史快照（覆盖对账仍逐条核对，缺路径照旧显式报缺并阻断）。

- Agent 任务认领与执行回执：认领有 token 门禁，心跳/检查点/交付/效果确认经唯一写入服务落 v2 事件流；断线期间执行端在本地保留待提交回执并暂停领取新写任务，恢复后按原幂等键补交，不重复生效。
- 用量统计：项目概览显示任务认领额度（运营节流，不是费用或成本硬限）与事件可配对的执行耗时；Token 与金额没有可核对来源，显式标「未计量」。
- 私有事实（`.工作台/`）的**显式备份与隔离恢复**：「项目信息」页里可以按事件提交边界取一份一致备份（清单含格式与事件 schema 版本、截止提交序号、逐份内容哈希与证据清单；同一提交边界重复备份幂等），落点由你选；备份位置**必须在项目外**（按真实路径判，项目外的 junction/symlink 指向项目内同样拒），备份完界面跟着读**刚落这一份**的位置（默认目录里恰有同名的一份也不会串）。**备份放在自己选的目录里也找得回**——在同一个输入框里改回那个位置点「查询这个位置」，清单/详情/隔离恢复就都在那个位置上按清单归属认领（换一个进程重启照样找得回），别的项目的备份不会被列出、打开或恢复；那个位置里只剩损坏或归不了属的条目时，界面会醒目告警并逐条说明跳过了什么，而不是说一句「这里没有备份」。恢复**只落在隔离目录**并逐项核验，塔台不会自动替换当前数据——替换与否由你本人决定。`.工作台/` 默认不进 Git，**被忽略或被提交都不等于已备份**；「Git 保存版本提醒」里也只报「备份状态未知」，但会说明备份入口已可用、入口可用同样不等于已经备份过。
- 19 个 stdio MCP 工具：读设计/进度、报任务、提异议、读图、**读六图完整状态**（`get_project_graphs`：四档读取＝全六图/单图/节点/关系，同一快照标识，超限给 total/returned/cursor 与 `incomplete` 标记，不静默截断；逐对象带状态键/界面短标与颜色/来源/映射/证据状态/有效版本/阻断原因/用户待验；模型待审线索单列）与 `project_entry` 的**六图摘要**、Flash 问答、**项目接续入口**（`project_entry`）与认领/回报写口（`claim_task`/`submit_task_result`）、需求与变更批次管理、受检施工图定义导入、待重绑出口（`rebind_task`）与入口体检（`doctor`）；`ask_flash` 会调用模型，内部可写概念补全层。`claim_task` 的 op 面：claim/renew/release/**reopen**（DESIGN 附录 F：reopen 是协调器专用的受控重开——已提交卡开新 attempt，旧 token 作废、旧结果永久保留，须带可取回的 `reopen_basis`；不是新工具，工具数不变）。工具数以 `src/mcp/tools/index.ts` 的注册表为唯一来源（`pnpm verify:v09-05` 对账，文档计数与注册表恒等）。

## 设计与施工方向

**典型协作流程（各环节用什么工具/模型完全由你决定，塔台不绑定任何品牌）**：任一会话与用户聊方向 → 设计角色（你本人，或你指定的高能力模型）审定设计书和施工图 → 塔台整理图关系并生成规划图 → 用户选定的执行 Agent 认领施工 → 低成本模型做审计/修复 → 关键节点独立终审 → 用户体验验收。

目标主界面提供项目图、设计书、施工图、聊天、实况与验收。三种主视图为功能全景、系统架构、施工依赖；空仓也能从图纸生成灰色规划图，颜色按实际任务和有效证据自动更新。内置 AI 语义整理（模型服务可配置）协助整理已审定图纸，程序检查和绘制，不由模型猜完成度。

Agent 接入目标项目后取得有效版本、当前任务与接续要求，在已有授权内执行、验证、回报并继续。塔台记录协作事实，进程启动、终止与目录隔离由外部协调器负责。人类下一工具/模型/档位教学与一键启动向导延期；当前增加的 Git 版本提醒只做观察，不自动提交或推送。

**以上为当前的设计和施工要求。各批次施工卡的逐卡状态与证据见 [施工图](PLAN.md)；独立验收与收口结论以 PLAN 与审计记录为准。范围、依赖与验收见 [设计及建设总图](DESIGN.md#117-v06-建设施工总图) 和 [施工图](PLAN.md)。

当前不具备本链路的完整自动接续、图纸派生与审计证据闭环；**桌面壳被正常关闭或强制结束时，其后端子树与 8787 端口的自动回收尚未交付**（现行为仅「下次启动报端口占用」提示＋手动清理；改为立卡交付，见 DESIGN §11.3 与 PLAN）；中大型/超大型支持须经自举、故障与规模验证。本机单用户优先，远程已有代码保持默认关闭。

## 怎么跑起来

前置：**Node.js >= 20**（`node -v` 自检；随包后端也复用系统 PATH 里的 node）＋ pnpm（用 Node 自带的 corepack 启用）。

```bash
corepack enable pnpm
git clone https://github.com/sannongwangluo/tatai.git
cd tatai
pnpm install
```

起服务（两个终端，各跑一条）：

```bash
pnpm dev:server    # 后端：http://localhost:8787（探活 GET /health）
pnpm dev           # 前端：http://localhost:5173
```

浏览器打开 **http://localhost:5173**，左栏「＋ 添加项目」填一个本地项目目录，即完成接入（塔台只往该项目的 `.工作台/` 写它自己的数据，见下节）。

想看架构图：选中项目 → 「技术详情」页签 → 点**「先解析」**。这一步分两段：先把源码**静态解析**成模块骨架
（tree-sitter，零模型调用），模块还没有人话名时，紧接着自动调一次模型服务起名（界面上会显示"正在给模块起人话名…"；默认服务与密钥见下节配置）。
解析在后台运行：有进度显示、可显式取消；断线或刷新页面可续看进度，取消不会写入半成品（上次完整结果原样保留并标注原因）。
模块起名需要 DeepSeek 密钥（`DEEPSEEK_API_KEY` 环境变量，或 `<全局数据目录>/config.json` 里的 `deepseek_api_key`）——
**没配也能用**：静态解析照常出图，模块名退回目录名；起名失败时结构图不受影响，按模块 id 显示并在横幅说明。

当前内置 Flash 默认连接本机网关 `http://127.0.0.1:3456`，调用 `/v1/chat/completions`；仅配置密钥不足以代替这个网关。使用其他兼容服务时，通过 `TATAI_DEEPSEEK_BASE_URL` 环境变量或全局 `config.json` 的 `deepseek_base_url` 设置可达基址，并核对实际模型配置。内置聊天配置与外部 agent 工具配置分别维护。

让 agent 主动汇报（MCP，推荐）：把下面这段加进你的 agent 的 MCP 配置，`args` 里的路径换成你 clone 的绝对路径。

```json
{
  "mcpServers": {
    "tatai": {
      "command": "node",
      "args": ["--import", "tsx", "C:/tools/tatai/src/mcp/index.ts"]
    }
  }
}
```

数据目录默认 `~/.tatai`，与网页端同源；若你把它改到别处，在配置里加 `"env": { "TATAI_HOME": "<你的目录>" }` 与网页端保持一致即可。
若你装了桌面壳（下节），同一份配置里 `args` 换成安装目录下的 `server/mcp.js` 即可（`%LOCALAPPDATA%\Tatai\server\mcp.js`）。

其他常用命令：

```bash
pnpm typecheck     # tsc --noEmit
pnpm build         # 前端产物 dist/
pnpm build:server  # 随包后端（含 THIRD-PARTY-NOTICES.txt，见"第三方声明"节）
```

桌面壳（可选，需要 Rust 工具链，且 PATH 里要有 node >= 20）：

```bash
pnpm tauri:dev     # 起壳窗口：beforeDevCommand 先 pnpm build:server 再 pnpm dev
pnpm tauri:build   # 一条命令打安装包：包装器构建 → 写构建戳 → 自动绑定 → src-tauri/target/release/bundle/{nsis,msi}/
```

两条都不需要你先手动跑 `pnpm build` / `pnpm build:server`——各自的前置命令会自动带上：dev 侧 `beforeDevCommand` = `pnpm build:server && pnpm dev`（每次起壳先产出 `src-tauri/resources/server`，约 2 秒），build 侧 `beforeBuildCommand` = `pnpm build && pnpm build:server`。**`resources/server` 在 dev 态也缺不得**：`bundle.resources` 无条件声明它，没有它壳一启动就报 `resource path 'resources\server' doesn't exist` 直接退出。

`pnpm tauri:build` 走的是**包装器**（`scripts/tauri-build.ts`）：构建成功后写一份**构建戳**（`scripts/lib/buildStamp.ts`，记本次构建的源码内容指纹），再自动跑 `pnpm package:bind` 把产物与源码绑定（`binding.json`）。**不要绕过包装器**：直接 `pnpm exec tauri build` 再单独跑 `pnpm package:bind` 会因**缺戳**被拒（写戳后源码又被改、或戳与当前源码不一致同样拒），不会写出绑定记录。

已知限制（照实写，不是"以后再说"）：安装包目前只出 **Windows**；WebView2 运行时与 node **都不随包**（装的时候由安装器联网拉微软官方引导器，运行时要 PATH 里有 node）；远程访问默认关闭，且不提供"允许公网"的开关（局域网绑通配地址另有一个**默认拒绝**的显式环境变量逃生口，见「远程访问」节最后一条）。

## 数据在哪

三层，互不重叠：

| 层 | 位置 | 进 git 吗 | 内容 |
| --- | --- | --- | --- |
| 工作台全局 | `TATAI_HOME` 环境变量 > 默认 `~/.tatai/` | 否 | 注册表 `registry.json`、`agents.json`、打包态日志 `logs/backend.log`、远程口令与写模式开关 `remote/`（只在开启远程时生成） |
| 项目私有 | `<项目根>/.工作台/` | **否（默认 gitignore）** | 设计书、待议、进度与 Gate、任务、聊天、变更流水、架构缓存、终端历史 |
| 项目公开 | `<项目根>/` 正文 | 是 | 代码、`AGENTS.md`、`README` |

把数据放别处就用环境变量，让网页端与 MCP 侧给同一个值即可：
`TATAI_HOME=/path/to/data pnpm dev:server`（Windows 命令提示符：`set TATAI_HOME=D:\my-tatai` 后再跑 `pnpm dev:server`）。

每个被纳管项目的 `.工作台/` 里是这些东西（`预置`＝空模板里就有；`程序自建`＝塔台在第一次需要时自己建，模板不预置——逐条标注的同一份树见 `templates/README.md`）：

```
.工作台/
├── design.md            设计书（界面「设计书」页签只读展示的就是它）            [预置]
```

## 远程访问（保留的既有实现，默认关闭）

本节保留已有配置说明；按现行设计，远程/手机端另列建设期，本轮不启用。默认启动只绑 `127.0.0.1`，零外部监听。另行启用局域网只读查看时，配置示例如下（类 Unix shell）：

```bash
TATAI_REMOTE=1 TATAI_HOST="<本机局域网IP>" pnpm dev:server
# 只读查看上例即可；确需远程写时，逐字带上写开关与确认语：
TATAI_REMOTE=1 TATAI_HOST="<局域网 IP>" TATAI_REMOTE_WRITE=1 TATAI_REMOTE_WRITE_CONFIRM="我确认开启远程写模式" pnpm dev:server
```

- **远程默认只读**：上例不开写模式，写接口一律 403。确需远程写操作时，另行按 `src/server/remote-config.ts` 的写模式开关与确认语配置；只读查看不需要它们。聊天、终端、记忆这类**私人数据**默认不对远程下发，各有独立的显式开关。
- **访问要口令**：`pnpm remote:token show` 生成/查看，`rotate` 轮换；远程打开 `http://<主机 IP>:8787/` 输口令登录。
- **怎么关写模式（立刻失效）**：`pnpm remote:write off`——运行期关，不用重启。
- **写模式时段怎么查**：`pnpm remote:write status`；每次翻转都在审计日志里留一条 `write-mode-on` / `write-mode-off`（带时间戳与来源）。
- **审计在哪**：`<全局数据目录>/logs/remote-audit.jsonl`（远程访问逐条留痕，含拒绝）。
- **不推荐公网直连**，四条理由：**无 TLS**（明文 HTTP）、**静态口令**（单 token 非多用户体系）、接口含 **PTY** 终端与文件写入（等于把本机 shell 挂上网）、响应含**私人数据**面。真要跨公网，套反代 + TLS，且反代必须对 SSE 关缓冲（nginx 写 `proxy_buffering off`），否则界面不刷新。
- **通配绑定逃生口（如实说明，别当成默认行为）**：另有一个显式环境变量 `TATAI_REMOTE_ALLOW_WILDCARD=1`，允许把服务绑到通配地址（`0.0.0.0` / `::`）——**默认拒绝**（不设它时绑通配地址直接拒启动）、**公网路径没有开关**（解析出公网地址一律拒），只有这个环境变量能放行，放行时日志打醒目 ⚠ 警告。开关本身的去留**已由用户 2026-09-24 裁定：保留**（不再列为待裁定项），**远程仍默认关闭**；`pnpm verify:s1` ⑤ 对这个放行路径有断言（DESIGN.md §12.1-20、附录 G-5）。
